# VS2022 运行说明

1. 使用 Visual Studio 2022 打开本目录的 `zuoyezuihou.sln`。
2. 安装“使用 C++ 的桌面开发”工作负载，使用 v143 工具集与 Windows SDK。
3. 选择 Debug / x64，按 Ctrl+F5 运行。调试工作目录已设为工程目录，数据文件统一读写本目录。
4. 原始默认管理员为 admin / admin；首次使用默认密码登录后，必须输入当前密码 admin，并设置至少6个字节的新密码。已有修改过的管理员密码继续有效。
5. 学生登录用户名现为学号，初始密码为学号；老师用户名和密码保持原来的设置。
6. 输入中文使用 UTF-8；源码及项目编译选项已统一配置。

## 修复内容

五个 C 源文件及相关头文件、项目配置已修改。包括函数声明类型冲突、switch 分支作用域、中文编码、输入长度和格式检查、空字符串检查、删除学生误删账号、学生同名冲突、容量不足产生孤立档案、重复成绩、课程满额清空旧成绩、平均分同步、零分最高科目显示、无成绩提示顺序、空教师列表显示和数据文件边界检查。

用户列表隐藏密码；密码采用随机盐 PBKDF2-HMAC-SHA256（100000次）保存，旧密码数据在加载后迁移。默认管理员首次登录必须修改密码。三次失败触发当前进程60秒登录冷却；重启程序会重置冷却。

数据写入先写临时文件再替换单个原文件，保存失败会报告并退出。两个数据文件之间没有跨文件事务保证。

## 现有数据

原始源码和数据备份位于上一级“修复前备份”目录。原数据测试均在临时副本中执行。
启动时迁移旧账号与GBK文字；学生姓名账号改为学号。检测到无法唯一映射的同名或冲突数据会拒绝加载，保留原文件。
现有样本中账号 1 没有相符学生档案，禁止其登录；学号 1234 的档案缺失对应账号，程序会恢复该账号（初始密码1234）。其他有效学生账号按学号迁移。
新数据格式不能直接交给旧版程序读取；恢复旧版时应同时恢复源码与两个数据文件。

## 验证

VS2022 / MSVC 实际编译 Debug、Release × x64、x86。
`python verify_fixes.py` 在临时副本中验证账号隔离、删除、重复成绩、平均分更新、密码非明文、重启登录、异常输入、损坏文件保护以及现有旧数据迁移与账号恢复。

本项目运行目标是 Windows + VS2022。原缺陷报告中跨 Linux/macOS 的要求不在此次运行验证范围内。

## 班级与成绩导入

- 管理员菜单：8 添加班级，9 查看班级（最多50个，名称不重复）。
- 学生菜单：4 选择或更换班级；查看成绩时显示当前班级。已有学生初始为未选择班级。
- 教师添加成绩时先选择班级，再输入该班学生学号；仍需具有管理员分配的授课权限。
- 教师菜单4：选择班级，统计当前教师任教科目的平均分和有效人数，仅统计有权限且已录入该科成绩的学生，零分参与统计，缺考或未录入不计入分母。
- 教师菜单8：选择班级，再输入CSV文件路径（不加引号）。文件使用UTF-8编码，可带BOM。可从Excel另存为CSV UTF-8，暂不直接支持xlsx。
- CSV每行三列：学号、科目、成绩。首行可为 `stuNum,course,score` 或 `学号,科目,成绩`，也可不带表头。不支持带引号的字段或字段内逗号。
- 科目必须与当前教师任教科目一致，学号必须已存在、属于所选班级且已分配给该教师，分数须为0–100的有限数值。已有成绩或文件内重复记录会拒绝导入，修改已有成绩请使用修改成绩菜单。
- 整批校验通过才导入；任何一行错误均报告行号且整批不写入。
- 新增 `classes.dat` 保存班级和学号对应关系，不改变原有两个数据文件的记录结构。备份时请同时备份三个数据文件。保存仍为单文件替换，没有跨文件事务保证。
- 测试：`python verify_classes.py`；原回归：`python verify_fixes.py`。测试均在临时目录运行。

## 表格显示

用户、班级、学生、成绩、可选教师以及排名列表均使用统一边框表格，按中文2列、ASCII字符1列的显示宽度补齐；过长字段用省略号截断，控制字符替换为问号，避免内容影响列位置。
管理员菜单10查看所有学生、11查看所有成绩；教师菜单9查看所有学生、10查看所有成绩（仅列出自己有授课权限的学生）。
无成绩显示“--”，不与真实零分混淆。请使用等宽字体，窗口至少120列；手工测试启动脚本会尝试设置为140列。
运行 `python verify_tables.py` 检查中英文混排、长班级名截断、各类列表与排名的列边框位置。
